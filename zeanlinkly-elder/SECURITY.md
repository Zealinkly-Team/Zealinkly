# 安全政策

## 报告安全漏洞

如果您发现本项目中的安全漏洞，请**不要**在 GitHub Issues 中公开报告。

而是，请通过以下方式私密报告：

### 报告方式

1. **邮件**: 发送到 security@example.com
   - 包含漏洞描述
   - 包含受影响的版本
   - 包含复现步骤（如有）
   - 包含您建议的修复方案（如有）

2. **GitHub Security Advisory**:
   - 如果您有 GitHub 账户，也可以通过 Security Advisory 私密报告

### 报告时间

请给我们合理的时间来修复漏洞：
- 关键漏洞（CVSS >= 9.0）：7 天内
- 高危漏洞（CVSS 7.0-8.9）：30 天内
- 中危漏洞（CVSS 4.0-6.9）：60 天内
- 低危漏洞（CVSS < 4.0）：90 天内

## 安全最佳实践

### 对于开发者

1. **不要提交敏感信息**
   - API 密钥、密码、令牌等
   - 这些应存储在环境变量中

2. **使用 HTTPS**
   - 所有网络通信应使用 HTTPS

3. **验证输入**
   - 验证所有用户输入
   - 防止注入攻击

4. **定期更新依赖**
   - 定期检查和更新依赖
   - 修复已知的安全漏洞

5. **代码审查**
   - 所有代码更改都应经过代码审查
   - 注意安全问题

### 对于用户

1. **使用最新版本**
   - 始终使用最新的应用版本
   - 及时更新以获得安全补丁

2. **保护您的凭证**
   - 不要与他人分享您的登录信息
   - 使用强密码

3. **启用 2FA（如可用）**
   - 启用双因素认证以增加安全性

4. **报告问题**
   - 如果您发现问题，请按上述方式报告

## 依赖安全

本项目使用以下措施来管理依赖安全：

- GitHub 依赖警报
- 定期的依赖审计
- 及时的依赖更新

## 许可证

本安全政策适用于所有 Zealinkly 项目的版本。
